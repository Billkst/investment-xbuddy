# AI 使用与验证记录

本项目使用 Codex 与并行研究代理辅助开发。用户在开发前明确了两项约束：实际预算为 3 小时；公司对比仅为案例，产品必须接受个性化自由研究目标。

## 参与环节

| 工具/角色        | 参与内容                                                   | 验证方式                                                     |
| ---------------- | ---------------------------------------------------------- | ------------------------------------------------------------ |
| Codex 主代理     | 需求对照、架构、界面、执行器、持久化、测试、交付文档与发布 | TypeScript、核心测试、真实 API 验收、Chromium 操作测试       |
| 需求复核代理     | 独立复核题意，审查状态机、模型分支、证据和日期逻辑         | 只读代码审查，mock fetch 重现边界问题                        |
| 金融接口研究代理 | 阅读扶摇与 iFinD 官方契约，测试认证和腾讯公开行情          | 实际只读 HTTP 请求；使用用户授权的本地凭据，不输出或猜测密钥 |
| Sites 技能/工具  | 应用骨架、用户身份、D1 与部署流程                          | 本地构建、迁移、发布终态检查                                 |
| Playwright       | 浏览器操作与截图                                           | 审批、报告、引用、导出、刷新、记忆、手机布局                 |

产品本身与开发过程中的 AI 应区分：初始实现阶段没有运行时模型凭据；后续用户提供 Groq key 后完成真实接入，详见文末。当前规划使用结构化输出及有限修复，只有用户主动选择才切换规则；产品构造数据入口已移除，文中早期阶段是开发历史。

## 已发现并修正的问题

1. **范围收窄过度**：初版计划把公司对比写成唯一范围。用户指出应支持个性化研究后，改为自由目标输入、动态标的/日期/关注点与受控工具选择。
2. **证券代码去重错误**：按六位数字去重会丢失 `000001.SH` 与 `000001.SZ` 中的一个。改为完整交易所代码，并增加测试。
3. **时间表达误解**：近一个月曾默认为一年。补齐周、月、半年、年及明确日期解析，无法可靠理解时请求澄清。
4. **指数误用财报工具**：构造模式曾在权限校验前返回数据。将指数检查前置；模型返回的已知证券类型也由服务端纠正。
5. **多年财报演示不完整**：三年目标曾只生成一年。改为按目标年数生成，并检查真实来源年份覆盖。
6. **原始字段映射错误**：扶摇历史字段是 `date_ms`、`close_price`，不能照搬常见 `date`、`close`；按官方契约修正并保留测试。
7. **财报截止日穿越**：UTC 日末与上海展示日期混用，会接受上海次日披露的财报。统一上海日界线，增加针对性回归测试。
8. **元数据缺失未降级**：缺时点或明显陈旧数据曾仍标“已验证”。增加缺失/过期质量标记，报告列出缺口，并禁止不可用证据进入推断。
9. **压缩丢失口径**：初版摘要只保留值和 ID。追加统计口径、质量说明、公式及输入证据，原始记录保持完整。
10. **暂停与审批交叉**：暂停时可能保留审批但隐藏入口。调整界面为存在待审批对象就展示，审批与计划版本绑定。
11. **执行预算仅在终态落库**：请求中断可能漏计尝试。增加请求前预算预留及进度保存，并在外部调用前检查暂停标记。
12. **模型输出边界过弱**：最初关键词拦截遗漏加仓与确定上涨。增加交易指令和收益承诺过滤、引用校验与回归测试；仍不将文本过滤描述为正式合规认证。
13. **UI 验收时序问题**：浏览器过早点击未完成 hydration 的页面。增加加载状态语义，测试等待实际初始化完成，再验证交互。

上述修正由 AI 代理实施并测试。该阶段没有把尚未发生的人工作业、真实模型验收或真实财报验收写成已完成。用户的人为修正主要发生在时间预算与产品范围上。

## 外部接口验证与限制

调研期间成功读取腾讯股票/指数公开行情，确认历史日线与最新快照的时点不同。扶摇无密钥返回 HTTP 200 + 业务错误；iFinD 无凭据返回认证失败。

随后相同腾讯、扶摇 HTTPS 请求在当前开发环境出现 `WRONG_VERSION_NUMBER`，应用真实行情验收因此未通过。保留正常 HTTPS 与明确失败状态，没有关闭证书验证、切换 HTTP 或偷偷填入构造价格。开发环境的网络问题不能算作真实金融接入成功。

该阶段测试只使用 `test-only` 假密钥与构造金融记录；未配置共享模型。

## 后续免登录体验调整

用户反馈登录门槛影响体验后，增加浏览器内临时工作区，复用既有 Harness；保持服务器个人数据的身份校验。AI 实现访客入口、临时存储与清除、构造数据约束、测试和文档。另一个审查 Agent 只读验证引擎的浏览器兼容性和无外部调用路径，指出 contextLimit、存储篡改和并发处理要求，由主 Agent 落实。

## 移除账号依赖与 AI 状态说明

用户进一步明确作品所有功能都应免登录使用。主 Agent 移除 ChatGPT 身份入口和前一版访客/账号分流，改为随机匿名 Cookie、服务端哈希会话和 D1 工作台，开放历史记录、研究记忆及真实数据模式。清空会原子撤销会话并删除当前工作台数据；旧账号数据没有公开或迁移。审查 Agent 只读检查浏览器隔离、Cookie、同源写入、并发清空与初始化请求。

当时解释开发时使用 AI 不代表网站运行时已接入模型；该阶段没有模型 key，规划是规则代码，报告是证据模板。界面与 README 直接标明“AI 未接入 · 规则运行”。没有创建模型账号、冒用开发环境凭据或宣称真实模型调用成功。

## 共享免费服务与个人密钥（后续增量）

用户选择“共享服务默认、访客可用个人 key”，并自行在 Groq 官方平台申请密钥，保存至忽略提交的本地 `.env`。主 Agent 使用该密钥完成真实连接及规划/报告链路，随后将 key 作为 secret 配置到站点后端。访客无需注册或登录。未使用公开泄露密钥，也未将开发助手额度作为网站后端。

AI 实现模型配置 UI、测试连接、RAM 中的个人凭据、仅持久化白名单元数据、Groq/OpenRouter 固定地址与不跟随重定向、配额预留和降级处理。只读审查 Agent 指出额度分别写入会造成空耗、个人与共享桶串用、中文估算偏小和当前研究来源显示错误，由主 Agent 修复并测试。采用 CHECK 约束与 D1 batch 实现整体回滚；真实运行时验证还修正 Cloudflare 不支持 `redirect:error` 的问题，改用 `manual` 并拒绝非成功状态。

用户指出 `CONTEXT_LIMIT=7000` 可能过小。检查确认其为字符压缩阈值而非模型窗口，调整至 16000，同时报告排除完整日线路径、保留首末样本与完整溯源元数据，模型实际读取压缩摘要与增量证据。原始证据不删除。真实验收使用构造金融数据，因此仅证明模型/执行链路，不能据此声称真实财报接入成功。

## 真实金融接入、国产模型与界面重构

用户指出金融数据仍待配置、iFinD 未使用、国内模型入口不足和界面复杂，并要求删除构造数据。随后用户提供扶摇 key。主 Agent 在不显示或提交密钥的前提下完成行情、利润表、现金流、估值调用，并将该 key 保存为站点 secret。真实 Groq 与扶摇研究链路通过；iFinD 因缺少独立 MCP 凭据仍未接入，UI 明确标注“未接入”。

研究子 Agent 核验国产服务官方 URL/模型/思考参数及 iFinD 认证契约；主 Agent 补入 DeepSeek、百炼千问、智谱、Kimi、豆包和硅基流动。发现 Kimi 不接受统一 temperature 后省略通用采样参数；专有参数只应用于核验过的默认模型。没有使用这些供应商的真实 key，故仅报告契约测试通过。

主 Agent 将主界面调整为目标输入、计划确认、结果阅读；移除模式与故障演练入口、常驻统计卡与右侧技术栏。结果置顶关键指标和主要发现，完整事实、任务、日志、证据库和上下文默认折叠。API 同步拒绝构造研究，旧演示记录退役而不改标真实。只读审查发现旧 demo 的暂停快捷路径仍可返回数据，已补上前置检查。修复扶摇指数快照单位和证据 raw 响应结构，保留安全网络错误码以便区分连接问题。

本轮 API 和浏览器使用真实扶摇数据，纯核心单元测试继续采用构造夹具。真实账户金融数据及截图只保存在忽略提交的本地测试目录，不进入公开源码。

## iFinD 从连接到完整研究、提交收尾

用户提供独立MCP密钥后，先完成初始化、JSON/SSE、工具发现和9工具清单展示。用户进一步明确全部纳入交付后，主Agent将9项只读工具纳入规划、执行、预算、审批、暂停、检查点、原文/数值证据、报告与导出；宏观和新闻目标不再被强制要求提供A股代码。

研究代理用授权凭据逐一探测真实工具，主Agent依据实际返回实施适配。发现宏观多返年份、摘要列错位、财报缺披露日、行情单位不明确、热门新闻缺发布日期等问题后，没有用模型猜补元数据，而是保存原表、过滤日期并标注待核对。MCP业务成功码为1，与扶摇的0分开处理。

只读审查代理复现并推动修正了：混合目标丢失财务任务、否定新闻仍调用、跨年月被缩成首月、未来日期倒置、握手期间停止未生效、候选文本包含交易建议、压缩后未核验数值重新进入模型、宏观表头与元数据单位冲突。每项修正均由主Agent实施，并加入有意义的回归测试。真实模型验收还发现宏观任务不应被证券市场参数校验阻断，已按工具区分。

主Agent完成真实Groq→iFinD→证据报告，以及新闻、公告、筛选的工作台API与浏览器验收。用户通过GitHub CLI网页授权恢复登录，由主Agent创建作品仓库。源码与历史在公开提交前检查密钥；真实金融返回和演示视频保存在源码仓库外，不将受限账户数据复制进公共仓库。
